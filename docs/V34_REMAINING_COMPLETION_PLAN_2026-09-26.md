## 2. 決定の区分

- 確定: iPhone/touch-first、TARGET→METHOD→FIRST CAST→MY SET→FIELD MODE。登録・商品検索・TRIP READYは必須通過点にしない。
- 確定: ownedとpackedを分離。不明・不適合をREADYにしない。研究商品を自動公開昇格しない。
- 仮決定: 下記P0→P1→P2→P3の順で進める。計測結果で同一優先度内を調整する。
- 案: 性能の数値予算、公開初期の重点プラン。実測・内容監査前に達成済みとしない。
- 廃止: 旧隔離画像の復活、SKU数だけを増やす完成判定、新しい画面wrapperの積み増し。
- 禁止: 無断merge/deploy/公開、外部送信サービス導入、保存データ破壊、テスト条件を緩めてgreen化。

## 4. 戻る・進むの実装契約（R02）

1. ホーム→結果→FIELDの主要画面移動をhistoryに記録。検索の一文字ごと・チェック一件ごとには積まない。
2. ダイアログ表示中の標準戻るはまずダイアログを閉じる。アプリ内閉じるで余分な履歴を作らない。
3. 戻る/進むで魚と釣法を復元し、現在の手持ちデータからセットを再計算。削除済み道具の古いスナップショットを復活させない。
4. ホーム復帰では検索語・フィルタ・一覧位置を維持。結果とFIELDは答えが見える位置に遷移。
5. 未保存の入力を失う条件を特定し、入力保持か明示確認で防ぐ。保存済みデータは履歴操作で巻き戻さない。
6. 初期履歴を重複追加しない。戻る連打を閉じ込めない。アプリより前の履歴に戻る通常動作を妨げない。
7. reload/不正state/旧形式/別タブは安全な画面へ復帰。URLに手持ち詳細など個人データを載せない。
8. ユーザー操作を再現する検査で確認。内部関数だけを直接呼ぶ検査に置き換えない。

## 5. 視認性の検査行列（R03）

対象: ホーム、検索0件、結果、釣法切替、MY SET不足/確認/適合、FIELD、手入力、商品読込中/失敗、持ち物、保存/プライバシー。

- 通常と200%文字、短名/長名、最上部/最下部、開いた詳細、入力時の縮小viewport。
- 重要な文・ボタン名は省略だけで意味を失わせない。主動線の横スクロール、下部ナビとの重なり、閉じられない画面を0にする。
- 頻用ボタンの実効領域44×44以上、FIELDの重要文14〜17px以上を既存契約として維持。
- コントラストは実際の前景/背景と状態を測定。数値目標を使う際は現行の公式基準を確認し、透明色・グラデーションも含める。ツール無警告だけで適合宣言しない。
- 色だけに意味を依存しない。focus順、見出し、入力名、状態の読み上げを確認。
- 屋外・濡れた指・片手の使いやすさはブラウザ寸法検査とは分けて実機記録。

## 6. 内容を増やす順序（R04/R08）

仮の第一群: 堤防サビキ、アジ/メバル、シーバス、ショアジギング、エギング、サーフのヒラメ/マゴチ。
第二群: 遠投カゴ・泳がせ・ぶっ込み、バス/トラウト、既存船釣り。
以後: 残る全プラン。優先群は既存V34の高頻度分類と今回の準備用途を基にした作業順で、計測済み利用頻度ではない。

各planのカード: 魚/場所/サイズ前提、釣法、FIRST CAST、竿、リール、巻いている糸、リーダー、仕掛け、取込み/取扱い/安全、持ち物、商品候補、出典、確認日、未確認点。

必要仕様と販売商品は分離。型番・仕様の確認はメーカー一次資料を使い、釣法判断とメーカー推奨を混同しない。安全やルールが絡む場所固有情報は最新の公的情報で確認する。外部画像を無断で取り込まない。

各群を「内容→候補→手持ちとの判定→持ち物→FIELD→offline」の一式で閉じる。58/58の商品充足だけを公開条件に置き換えない。V34全体の158プラン確認・63対象の視覚方針を勝手に縮小しない。

## 7. 実機受入シナリオ（R10）

| ケース | 操作と成功条件 |
|---|---|
| 初心者・未登録 | 魚から釣法と最初の1投へ。登録を強制しない。約5秒の理解目標を実測 |
| 手持ちあり | 魚から今回のセットへ。約15秒の準備目標を実測。適合理由と不足が分かる |
| 現場 | FIELDを開き約3秒で次の行動を説明できる。無反応時の変更が分かる |
| 迷い・復帰 | 釣法変更、手入力、持ち物、戻る/進む、キーボード、再読込で選択と保存が破綻しない |
| 通信・保存 | 機内モードで事前cache済みの起動と主要導線。未cache初回は対応可能範囲を明示。再起動/更新でデータ保持 |
| 読みやすさ | 文字拡大、VoiceOver、明るい屋外、片手操作。重要情報を読めて操作できる |

機種、iOS版、Safari/PWA、SHA、通信/文字設定、所要時間、誤操作、録画/画像、PASS/FAILを残す。時間は内部目標であり、未計測の性能保証にしない。
端末をこちらで操作できない場合、ユーザーには一度にこの短い受入テストを依頼する。自動テストを物理端末確認として扱わない。

## 8. 進め方・復旧・残さない曖昧さ

- 各差分でGoal / 対象file / 非対象 / 受入条件 / rollbackを短く固定。
- 対応するローカル検証→一つの意味のあるhead→関連CIを確認。失敗は原因と証拠が増える方法で調べ、無意味な再実行を避ける。
- 画像とデータは別の出典・承認台帳を保つ。コード合格を権利承認にしない。
- 性能改善のために画像の識別性や安全情報を削らない。既存保存形式の変更は必要性が証明された場合だけ。
- 完了報告はID/差分/SHA/検証範囲/残件を記載。CI green≠製品完成、製品候補≠公開承認。
- 期限は原因未確定のR01と実機確認前に断定しない。まずR01〜R03を一巡して残工数を見直す。
